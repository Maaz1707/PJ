# Parag Jewellers ring try-on

**Product asset correction:** The original generic sample-model flow described below has been superseded. The current application resolves models and galleries exclusively by catalogue product ID, with three distinct product-specific prototypes and 43 explicit missing-model records. Exact approved CAD is missing for all 46 products. Read [PRODUCT-ASSETS.md](PRODUCT-ASSETS.md) and [PRODUCT-ASSET-INVENTORY.json](PRODUCT-ASSET-INVENTORY.json) for the current architecture, assets and validation. `npm run models:generate` now runs generate-product-assets.mjs. The generic demo GLBs are retired and are never a product fallback.

## Audit and implementation choice

The existing shop is buildless JavaScript with hash routes, 46 catalogue products, seven ring products, and a separate market-rates endpoint. The Sites edition packages those files with a Vinext Worker; the GitHub edition serves public/ with a Vercel function. There were no CAD/GLB product assets. Migrating this working shop to React/Next.js would add unnecessary work and dependencies, so the feature uses browser ES modules alongside the existing app. No backend endpoint or paid service was added.

The home layout, catalogue, bag and rate API are unchanged. Ring detail pages gain **Try It On** and **Explore in 3D**. Existing checkout remains a preview; this feature does not enable payments.

## What is implemented

- Lazy-loaded Three.js viewer, GLB loading, drag/touch orbit, zoom buttons/pinch/wheel, reset, fullscreen where supported, three metal finishes and three original demo shapes.
- Explicit camera start, front/rear preference, permission/busy/missing-camera messages, stop/close, and cleanup on navigation, page exit and backgrounding.
- Genuine MediaPipe Hand Landmarker video inference, 21 landmarks, one hand, worker execution with throttled local main-thread fallback. No fabricated landmarks are used by the application.
- Configurable finger selection and model placement; landmark-derived position, orientation and relative scale; time-based smoothing; hiding on lost tracking; optional debug landmarks.
- A depth-only cylinder approximates the finger to hide the back of the band. It does not segment skin or reconstruct its geometry.
- Explicit photo capture composites the actual video and transparent WebGL buffer with consistent letterboxing and mirroring. Camera turns off after capture. Preview, download, retake, and native file sharing where supported.
- Product thumbnails, metal selection and return to the product page; selection updates the existing metal controls.
- Responsive dialog, keyboard focus/escape, reduced-motion styling and measured inference timing under fit tips.

Full library licences and a SHA-256 asset manifest are included with the vendored files. First camera use downloads the model and the applicable WASM binary, roughly 20–25 MB plus runtime code. Alternative WASM builds are supplied for browser compatibility. There is no subscription or inference API bill; ordinary hosting bandwidth limits still apply.

The three GLBs are original procedural demonstration geometry, generated by generate-demo-rings.mjs. They are explicitly labelled as shape studies, not the product in the catalogue photograph. Gemstones use faceted reflective material, not physically accurate diamond ray tracing. RoomEnvironment supplies local procedural reflection lighting; no HDR image service is used.

## Run and replace assets

`npm test` in the GitHub checkout runs the pure geometry and camera lifecycle tests using Node 22. To regenerate the supplied demo GLBs, run `npm run models:generate`. No runtime npm packages are required because the pinned browser files are vendored.

For browser development tests, install Playwright as an optional test-only dependency (`npm install --no-save playwright`, then `npx playwright install chromium`). Serve the storefront on localhost:8081 with its existing local preview or Vercel development server. Run `node check-tryon.cjs` and `node check-camera.cjs`. For the genuine inference test, save the sample image URL listed below to `test-fixtures/hand.jpg`, then run `node check-tracking.cjs`. That script also accepts TRYON_BASE with a complete product URL for a different local server. Browser tests can use CHROME_PATH to select an installed Chrome binary. The synthetic camera and image fixture are test inputs, not substitutes in production.

Deploy the existing repository to Vercel with Other preset and public output; no build or paid API keys are needed. Camera requires HTTPS (or localhost), WebGL, camera permission and browser WASM support. The supplied files are ready to serve. An import map resolves `three` to the vendored runtime.

For exact product models, export triangulated GLB from Blender/CAD with applied transforms. Use local Y as the finger/hole axis and +Z as the setting direction. Normalize the inner radius to 1, centre the hole at the origin, and name stone materials `gem` and metal materials `metal`. Add model metadata in products.js and associate it with the matching product ID rather than assigning a generic study. Preserve licence/ownership information. Adjust anchor (fraction from MCP to PIP), positionOffset (in finger-radius units), scaleMultiplier, and selected finger per asset. Validate with real hands before removing the demonstration label. Size is a visual ratio, not millimetres.

New categories should implement separate landmark adapters returning the same transform contract. Earrings require face tracking plus explicit ear-position approximation; necklaces require pose/shoulder tracking. Neither is implemented or offered in the UI.

## Validation and limitations

Automated validation is run on Windows desktop Chrome using headless software WebGL. Tests cover:

- Geometry translation, rotation, scale, letterboxing, invalid landmarks, smoothing and pending camera-permission cancellation.
- All three GLBs, finish switching, zoom/reset, mobile viewport overflow, dialog close and permission-denied/missing-camera states.
- Actual MediaPipe inference on a moving video fixture made from Google's official hand-image sample. Tests verify detected movement moves the 3D ring, blank frames hide it, and capture/download, retake, camera switch and stream cleanup work. Test-only camera substitution is confined to the test file and is never shipped in the storefront runtime.
- The existing catalogue, search, sorting, wishlist and preview shopping-bag regression checks.

The native browser getUserMedia granted path was also exercised with Chrome's synthetic test camera, including closing the dialog during hand-tracker initialization. Compiled Cloudflare/Vinext output served the model, module, WASM and GLB files correctly and passed the moving-fixture inference/capture flow. Warm inference samples in this headless software-rendered environment were 89–154 ms, with longer cold initialization. These measurements do not establish performance on physical customer devices.

The test fixture source is https://storage.googleapis.com/mediapipe-tasks/hand_landmarker/woman_hands.jpg . It is not a customer's image and is not a production asset. Browser test scripts explicitly label the synthetic video input; they do not certify live-camera realism.

**Not yet validated:** physical camera sessions with moving live hands; actual iOS/Android devices; different skin tones, hand sizes, lighting and camera optics. A mobile viewport test is not a mobile-device test. These must be checked before commercial rollout. Native sharing/fullscreen availability depends on browser/OS and requires manual testing on devices that support those APIs. Headless timing is diagnostic only, not a promised FPS.

Monocular landmarks cannot give physical ring size, accurate skin depth, guaranteed anatomical fit or realistic occlusion for every pose. The setting is biased toward the visible side; palm/back-of-hand ambiguity and extreme angles can flip orientation. Fast movements or covered finger bases may lose tracking. Ring sizing, diamond optics, store inventory and payment remain outside this prototype.

## Privacy

No camera frames or photos are sent to a server. Model inference stays in the local worker or local fallback. No recording, analytics capture, automatic image storage or camera access on page load is implemented. Photos use temporary in-memory Blob URLs, revoked on replacement/close. Download and native share require explicit actions. Browser permission prompts still apply.
